Getting Started

1. Pick your practice cluster

You need a disposable Kubernetes cluster (ideally one control-plane plus two workers) and kubectl configured for it. Find its context:

kubectl config get-contexts

2. Tell the game which context to use

There is no default; the game only ever targets the context you name here:

export CKA_GAME_KUBE_CONTEXT=<your-practice-context>
kubectl config use-context "$CKA_GAME_KUBE_CONTEXT"

4. Join the shared scoreboard (optional)

To compete with others, point your CLI at the hub. Ask the hub owner for the join token, then in the terminal where you run cka-game:

export CKA_GAME_SERVER=http://<hub-ip>:8000
export CKA_GAME_TOKEN=<token from the hub owner>
cka-game whoami --set "<a unique name>"
cka-game sync          # send any progress you already have
cka-game scoreboard    # ranking in your terminal

After that, check, hint, reveal and reset update the board automatically; if the hub is unreachable the command still works and cka-game sync catches up later. Pick a name nobody else uses, or the hub will reject your scores.

5. Start the game

You're already looking at the web board (that means cka-game serve is already running!). Next, in another terminal:

Tip: activate the virtualenv once per terminal session so you can just type cka-game instead of .venv/bin/cka-game every time. (A permanent alternative: pipx install -e . installs the cka-game command globally, no activation needed.)

source .venv/bin/activate
cka-game whoami
cka-game start <scenario-id>
cka-game list
cka-game show <scenario-id>
cka-game hint <scenario-id>
cka-game check <scenario-id>
cka-game reveal <scenario-id>
cka-game reset <scenario-id>
cka-game score
cka-game scoreboard
cka-game sync
